## Engineering approach

- **Infrastructure as code.** Terraform defines the platform; Helm, GitHub Actions, and Azure DevOps deliver it. Every change traces to a commit.
- **Least privilege.** Scoped IAM roles and workload identity at runtime, short-lived OIDC credentials in pipelines, no long-lived keys.
- **Verified delivery.** Validation, tests, security scans, immutable images, and post-deploy smoke checks.
- **Observability and load.** Prometheus, Grafana, and CloudWatch alarms, plus load tests that exercise autoscaling.

## About this site

A static site on GitHub Pages. The homepage is one continuous 3D world (three.js r160, vendored in `vendor/`): the sun in the middle, the flagship islands on their orbits around it, and a ring of ten climate zones, one per Code Clinic domain. Case studies, the all-projects table and the list view are plain HTML generated by one Node script and committed, because Pages serves the repository as it is.

The whole world shares one daytime. There is no day/night switch and no weather control on the world page; the capital is always sunny. Zones differ by their own air and terrain, not by time of day. The three original case-study heroes keep their own sky control.

### Weather spheres and blending

Two things work together.

**Zone-local air (what you see from far away).** Each zone draws its own sphere from `air.sphere`: two soft camera-facing glows in its haze colour (not affected by fog, so they keep their colour at any distance), an optional low-poly cloud canopy, one large landform, and a sparse set of larger weather particles. In the whole-world overview all ten are visible at once and stay different; the capital view shows the zones within the camera’s field of view. There is no shell and no outline; the glow fades towards its edge.

**Camera air (what surrounds you).** Every frame each zone gets a weight from the camera focus point: 1 inside 0.75 × its radius, falling smoothly to 0 at 2.3 × its radius. Weights are normalised when they overlap and the rest goes to the neutral base sky; zoomed far out all weights fade. Sky gradient, fog, hemisphere and sun light, cloud tint and lamp level are the weighted sums. As a zone's weight rises its own glow and canopy fade and its full particles come in, so entering a zone is one continuous change.

**Detail tiers.** Far: island props are hidden beyond 170 units (back under 145), the zone’s opaque islands share one baked mesh, and particles smoothly approach 14 % density with larger flakes. The capital’s islands use one-mesh copies beyond 150 units (back under 120); both paths preserve baked vertex colours. Zone and island views restore the individual meshes and full props. Off-screen particle updates are culled, and particles fade out between 360 and 420 units. Decor modules rest outside their zone. Resolution uses actual frame intervals, drops after three slow samples, and recovers after eight good samples with a cooldown. Reduced-motion views request frames only after input, resize, visibility or asynchronous scenery changes; list view cancels the animation request.

### Zone config

A zone is an entry in `zones` in `data/world.json`. No engine code is needed for a new or changed zone.

```json
{
  "id": "finops", "n": 7, "name": "Cost Optimization & FinOps", "short": "FinOps", "range": [31, 35],
  "icon": "cactus", "color": "#e0a100", "mode": "day", "climate": "Scorching desert, heat shimmer", "blurb": "…",
  "sky": ["#f0a050", "#ffd08a", "#f3c27a"],
  "ground": "desert",
  "air": {
    "fog": ["#ffd08a", 55, 220],
    "hemi": ["#fff0dc", "#c9954f", 1.3],
    "sun": ["#ffb060", 1.55],
    "cloud": "#fff0dc", "lit": 0,
    "sphere": { "haze": "#ffc46b", "strength": 0.6 },
    "particles": { "type": "heat", "count": 240, "color": "#fff0dc", "size": 0.3 },
    "flora": ["cactus", "cactus", "rockSand", "dune"],
    "creatures": ["vulture"],
    "decor": "desert",
    "spin": 0.012,
    "built": true
  }
}
```

| Field | Meaning |
|---|---|
| `n`, `range` | Position on the ring (zone `n` sits at −90° + 36° × (n − 1)) and the Code Clinic numbers it holds |
| `sky` | Top, horizon and bottom colours of the sky gradient |
| `ground` | Island style: one of the climates in `world.js` (`meadow`, `desert`, `castle`, `snow`, `city`, `volcanic`, `tropical`, `forest`, `rocky`, `ice`, `village`, `rainy`) |
| `air.fog` | Colour, near, far |
| `air.hemi`, `air.sun` | Sky colour, ground colour, intensity; sun colour, intensity |
| `air.cloud`, `air.lit` | Cloud tint; how much lamps and windows glow 0–1 (weather, not night) |
| `air.sphere` | What makes the zone readable from afar. `haze`: colour of the soft glow around the zone, `strength` 0–1. `canopy`: `[shape, colour, puffs]` with shape `cap` (cloud over the zone), `column` (smoke) or `ring` (cloud below a summit). `terrain`: one large landform for zones without a decor module: `scale`, `ground`, `flora` as `[kind, count, size]`, `shapes` as `[cone|box|disc, colour, x, z, width, height]` |
| `air.particles` | `type` is one of `snow`, `motes`, `heat`, `dust`, `ember`, `rain`, `gust`; plus `count`, `color`, `size` |
| `air.flora` | Instanced props placed on every island of the zone: `tree`, `pine`, `pineSnow`, `palm`, `cactus`, `rockSand`, `rockGrey`, `rockLava`, `crystal`, `drift`, `dune`, `pond` |
| `air.decor` | Name of a module in `zones/` that adds the centrepiece, creatures and special effects; loaded on demand. `null` for none |
| `air.creatures` | Descriptive list of what the decor module animates |
| `air.spin` | How fast the islands of the zone orbit its centre, in radians per second |
| `mode`, `icon`, `color` | Used by the list view, the case-study pages and the labels |

## Add a project, add a zone, rebuild

Node 20 or later. Nothing to install.

**Project**

1. Add the repository to `data/projects.json` (or update `../_audit/projects.json` and run `node scripts/build.mjs --sync`, which copies public repositories only and drops audit housekeeping notes).
   Required fields: `name`, `title`, `summary`, `domain`, `stack`, `repo_url`, `outcome`, `status`, `validation_level`, `known_limitations`, `next_steps`, `visibility: "PUBLIC"`, `archived`. Optional: `demo_url`, `challenge_number`, `last_push`.
2. Run `node scripts/build.mjs`, then `node scripts/check-links.mjs` (add `--external` to request every repository and demo link).
3. Commit the data and the generated files together. CI runs the same commands and fails if the committed output is stale.

`challenge_number` 1–50 puts the island on its slot in the matching zone, replacing the uncharted island there. `archived: true` puts it on the Archive islet. Anything else is placed by its `domain` text, and falls back to the capital; to override, add it to `placements` in `data/world.json`. Every project gets an island, a label that links to its generated case study, a row in the all-projects table and a sitemap entry. A richer write-up goes in `content/<repo-name>.html`.

**Zone**

1. Edit or add the entry in `zones` in `data/world.json` (format above). Keep `n` and `range` unique.
2. Optional: write `zones/<name>.js` for the centrepiece and creatures and set `air.decor` to `<name>`. The module exports `default function build(api, zone)` and returns `{ update(t, dt, weight, appear, camera) }`; use `weight` to fade what it adds. `zones/tropical.js`, `zones/ice.js` and `zones/desert.js` are the examples.
3. Run `node scripts/build.mjs` and commit.

## Workspace and file organization

Use only the existing `cloud-portfolio` checkout. Before starting implementation, fetch/prune remote references, inspect local changes and worktrees, fast-forward `main` when safe, and remove only branches verified merged into it. Keep `main` plus the current work branch locally; preserve any unmerged work. Push changes or open PRs only when explicitly requested. The intentionally deleted local `AGENTS.md` stays unstaged; do not restore it during cleanup.

Keep the public entry points and existing asset paths stable. `data/` and `content/` are generator inputs; `projects/`, `index.html` and `world/placement.json` are generated output. `zones/` holds biome modules, `vendor/` the pinned renderer, `assets/` original project evidence, and `scripts/` build and validation tools. Reorganizing the public files adds import and URL risk without removing duplicate implementations; the world and case-study renderers intentionally preserve their different behavior.

Ignored local files have three purposes: `memory/screenshots/` contains current visual comparisons, `memory/world-preview/` contains raw profiling JSON, and `memory/.dev-instructions/` retains historical notes and unique migration code. `memory/README.md` is the current handoff. Disposable Lighthouse reports, old CI downloads, superseded screenshots and merged PR drafts can be removed after review. Keep the existing browser test tools in ignored `node_modules/`; they are not production dependencies.
